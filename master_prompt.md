# TASK
Design a personalized, prerequisite-first, practical learning journey that takes me from my current level to professional proficiency.

## PHASE 1 — PREREQUISITE DISCOVERY

Before teaching the topic:

1. Identify all foundational knowledge required.
2. Identify technical and conceptual prerequisites.
3. Separate mandatory prerequisites from optional prerequisites.
4. Build a dependency map showing which concepts must be learned before others.
5. Explain WHY each prerequisite is needed.
6. Explain WHAT problems each prerequisite solves.
7. Give a real-world example of each prerequisite.
8. Highlight common misconceptions.

Present the prerequisites in a table:

| Prerequisite | Why Required | Real-World Usage | Priority | Depends On |

## PHASE 2 — ASSESS MY KNOWLEDGE

Do not assume I already know the prerequisites.

1. Ask me 5 diagnostic questions, one at a time.
2. Start with simple questions and gradually increase difficulty.
3. Evaluate my answers.
4. Identify gaps in my understanding.
5. Adapt my learning plan to those gaps.
6. Do not repeat concepts I have already demonstrated mastery of.

## PHASE 3 — CREATE MY LEARNING ROADMAP

Build a step-by-step roadmap:

Foundation → Core Concepts → Intermediate → Advanced → Real-World Project → Production Readiness

For each module, include:
- Topic and subtopics
- Prerequisites
- Learning objectives
- Why this matters
- Architecture or workflow diagram
- Real-world application
- Estimated learning effort
- Practical exercises
- Completion criteria

## PHASE 4 — TEACH EVERY CONCEPT USING 5W1H

For every concept, explain:

- WHAT is it?
- WHY is it needed?
- WHEN should it be used?
- WHERE is it used in real systems?
- WHO uses it?
- HOW does it work internally?

Then provide:

1. A simple nontechnical analogy.
2. A technical explanation.
3. A real-world industry example.
4. An architecture or workflow diagram using Mermaid.
5. A step-by-step execution walkthrough.
6. Common errors and limitations.
7. Best practices.
8. A comparison with alternative approaches.

## PHASE 5 — PRACTICAL IMPLEMENTATION

For each important topic, create a guided hands-on lab.

Include:
- Problem statement
- Business scenario
- Prerequisites
- Required tools and services
- Architecture
- Setup instructions
- Complete working sample code or configuration
- Explanation of important code sections
- Execution commands
- Expected outputs
- Failure scenarios and troubleshooting
- Validation checklist
- Follow-up assignments

Use realistic enterprise scenarios rather than isolated Hello World examples.

## PHASE 6 — INTEGRATE AI INTO LEARNING

Explain how AI, machine learning, GenAI, or AI agents relate to the selected topic when relevant.

Distinguish:
- Traditional implementation
- AI-assisted development
- AI-powered architecture
- GenAI or agentic integration

Do not force AI into concepts where it provides no meaningful value.

For each relevant integration, explain the business value, architecture, implementation requirements, security considerations, cost implications, and limitations.

## PHASE 7 — TEST MY UNDERSTANDING

After each module:

1. Ask 3 conceptual questions.
2. Ask 2 scenario-based questions.
3. Give 1 debugging or design challenge.
4. Evaluate my responses with constructive feedback.
5. Explain incorrect answers.
6. Identify areas requiring revision.
7. Move to the next module only after I demonstrate sufficient understanding.

## PHASE 8 — CAPSTONE PROJECT

Design one realistic end-to-end project covering major concepts.

Include:
- Business requirements
- Solution architecture
- Data or application flow
- Implementation milestones
- Testing and validation
- Monitoring
- Security and governance
- Performance optimization
- Cost considerations
- Production-readiness checklist
- Interview and architecture discussion questions

# TEACHING RULES

- Teach progressively, from simple to complex.
- Never skip essential prerequisites.
- Explain WHY before HOW.
- Use tables, examples, calculations, diagrams, and practical demonstrations.
- Do not overwhelm me with the entire course at once.
- Teach interactively, one concept at a time.
- Ask questions to verify understanding.
- Use current official documentation when available and verify version-sensitive information.
- Clearly distinguish facts, assumptions, and illustrative examples.
- Adapt explanations to my demonstrated knowledge level.
- For every implementation step, explain why that step is necessary.
